# H5 파일럿 사례 (개발용)

H5: 근거 카드가 있으면 정비 가이드(LLM)의 잘못된 조치가 줄어드는가. 본 실험 전에 **방향(B가 A보다 낮은가)** 만 본다.

- 사례 10개. 판별기 작성자(양수빈)의 내부 모의 생성기로 만들었다. 엔진과 같은 가정을 공유하므로 근거 카드가 실제보다 잘 맞을 수 있다. **본 실험은 신원민 님의 블라인드 사례로 다시 한다.**
- 사례는 엔진 결과를 보기 전에 고장 종류·seed·크기를 정해 두고 만들었다. 엔진이 맞든 틀리든 그대로 넣었다.
- 센서 고장, 설비 고장, 동시 이상이 섞여 있다. 근거 카드의 측정 상태는 정보 부족·확인 대기 5건, 확인됨 3건, 의심 1건, 일부 의심 1건이다.

## 파일

`cases.jsonl` 한 줄이 한 사례다.

| 필드 | 내용 | 조건 A | 조건 B |
|---|---|---|---|
| `case_id` | P01~P10 | O | O |
| `alarm` | 설비 이름, 알람 항목(예: 진동 높음), 알람 뒤 지난 시간(분) | O | O |
| `observations` | 설치 센서의 최근 30초 값 (설정값, 토크, 전류, 진동, 온도) | O | O |
| `evidence_card` | 판정 엔진 v1.1의 근거 카드 (`engine/handoff.py`) | X | O |

## 실행 규칙 (박소영 님)

- A: `alarm` + `observations`만 넣는다. B: 같은 내용 + `evidence_card`.
- 두 조건 모두 같은 모델, 같은 프롬프트 틀, 같은 온도. 프롬프트와 모델 이름을 결과와 함께 적는다.
- 사례마다 3회 반복한다.
- 출력은 기획안 H5의 형식을 따른다. 여러 행동을 담을 수 있다.
  ```json
  {"actions": [{"type": "정비|정지|센서 점검|추가 확인|운전 지속", "target": "...", "when": "즉시|확인 후|다음 정비"}], "reason": "..."}
  ```
- 결과 파일 예: `eval/h5-pilot/runs/<모델>-<A|B>-<반복>.jsonl` (`{"case_id", "output"}` 한 줄씩)

## 정답과 채점 (신원민 님)

- 정답(사례별 고장, 범주)은 **레포에 없다.** 양수빈이 신원민 님께 따로 전달한다. LLM 담당은 정답을 보지 않는다.
- 채점은 기획안 H5의 맥락 채점표(안전 / 위험 / 불필요)로 한다. 채점할 때는 A·B 조건을 가린다.
- 생성 스크립트는 고장 목록이 들어 있어 레포에 올리지 않았다 (양수빈 보관).
