STEEL MIND · AGENT 시나리오 설계서

재미는 Agent들의 말에서 나옵니다

STEEL MIND에는 쓰러뜨릴 적이 없습니다. 플레이어가 고민하는 대상은 Agent들의 말뿐입니다. Agent가 뻔한 말을 하면 정답이 보이고, 정답이 보이면 게임은 끝납니다. 이 문서는 Agent가 "그럴듯하게 엇갈리도록" 만드는 규칙입니다.

작성 박소영(게임 시스템·Agent 구조) · 2026-11-09 · 함께 볼 사람: 신원민(시나리오·점수), 김다영(Agent 응답), 양수빈(화면)

01고민이 생기는 공식

플레이어가 20초 동안 진짜로 고민하려면 세 가지가 동시에 있어야 합니다. 하나라도 빠지면 선택이 쉬워집니다.

그럴듯한 반대 의견× 시간 압박× 나중에 돌아오는 대가= 고민
반대 의견이 약하면

"생산 Agent가 억지를 부리네" → 안전만 누르면 끝. 고민이 없습니다.

시간이 넉넉하면

표를 계산해서 정답을 찾습니다. 퍼즐이 되고 현장 감각은 사라집니다.

대가가 바로 보이면

손해가 적은 쪽을 고르면 됩니다. "지금은 괜찮은데…"라는 유혹이 없습니다.

02Agent 시나리오 작성 규칙 6가지

사건을 새로 쓰거나 Agent 대사를 고칠 때 이 규칙을 지킵니다. 대사 예시는 MVP 사건 1(사상압연기 온도 상승)입니다.

① 모든 Agent는 자기 자리에서 맞는 말을 한다

악역 Agent를 만들지 않습니다. 생산 Agent가 틀린 사람이 되는 순간 플레이어는 고민하지 않습니다.
나쁜 예생산: "안전 같은 건 나중에 생각하죠. 일단 돌립시다."
좋은 예생산: "속도를 유지해야 오늘 주문량을 맞춥니다. 감속하면 남은 코일 출하가 늦어져요."

② 의견은 반드시 갈린다 (만장일치 사건 금지)

Agent가 모두 같은 선택지를 추천하면 그 사건은 버튼 누르기입니다. 최소 2개 선택지가 추천을 받아야 합니다. 2:1:1이나 2:2 구도가 가장 좋습니다.
나쁜 예4명 모두 "감속 후 점검"을 추천
좋은 예속도 유지 1(생산) · 감속 점검 2(설비·품질) · 정지 1(안전)

③ 이유는 그 Agent가 지키는 숫자로 말한다

Agent마다 관심 지표가 다릅니다. 같은 상황도 생산은 출하량으로, 설비는 고장 시간으로, 안전은 사람으로 봅니다. 이유가 겹치면 Agent를 나눈 의미가 없습니다.
나쁜 예설비: "위험하니까 감속하죠." / 안전: "위험하니까 멈추죠."
좋은 예설비: "이대로 오르면 롤이 상해 더 오래 멈춥니다." / 안전: "설비 이상이 커지면 근처 사람이 먼저 다칩니다."

④ 당장의 이득에는 나중의 청구서를 붙인다

유혹적인 선택지는 지금 숫자가 좋아 보여야 하고, 대가는 다음 사건에서 돌아와야 합니다. 그래야 "지금은 괜찮은데…"라는 고민이 생깁니다.
나쁜 예속도 유지 = 즉시 안전 −50, 바로 실패
좋은 예속도 유지 = 생산 +12, 대신 설비가 달아오른 채 다음 사건 시작(안전 −5)

⑤ 쟁점 요약은 편들지 않는다

Agent 발언 뒤에 나오는 한 줄 요약은 무엇과 무엇을 맞바꾸는지만 말합니다. 답을 알려 주면 Agent 회의가 무의미해집니다.
나쁜 예"안전이 제일 중요하니 정지하는 게 좋겠습니다."
좋은 예"납기를 지킬지, 더 큰 정지와 사고를 막을지가 쟁점입니다."

⑥ 시간이 다 되면 가장 쉬운 유혹이 실행된다

결정을 미루는 것도 결정입니다. 시간 초과 시 기본 행동은 "아무것도 안 바꾸기", 즉 속도 유지처럼 가장 위험하지만 가장 편한 선택으로 둡니다.
나쁜 예시간 초과 = 가장 안전한 선택 자동 실행(기다리는 게 이득)
좋은 예시간 초과 = 속도 유지 / 무전 후 계속(기다리면 손해)

03Agent 캐릭터 시트

LLM에게 주는 페르소나이자 대사를 쓸 때의 기준입니다. 캐릭터는 팀 시안의 작업자 캐릭터를 Agent 색으로 바꿔 씁니다.

생산 Agent
지키는 지표: 생산량 · 납기
성격
급하고 현실적입니다. 오늘 목표를 놓치는 것을 가장 싫어합니다.
말투
짧고 숫자로 말합니다. "남은 코일", "출하", "오늘"을 자주 씁니다.
강하게 주장
라인을 멈추거나 늦추자는 의견이 나올 때
역할
유혹을 맡습니다. 가장 편하고 위험한 선택지를 그럴듯하게 만듭니다.
생산또 멈추면 오늘 목표는 못 맞춥니다. 무전으로 알리고 라인은 계속 돌립시다.
설비 Agent
지키는 지표: 설비 수명 · 정비 비용
성격
신중하고 멀리 봅니다. "지금 10분 vs 나중 하루"로 생각합니다.
말투
원인과 결과를 이어 말합니다. "이대로 가면 …해서 더 오래 멈춥니다."
강하게 주장
설비가 무리하고 있다는 신호가 보일 때
역할
중간안을 맡습니다. 감속·점검처럼 양쪽을 조금씩 지키는 선택지를 추천합니다.
설비급정지는 설비에 부담이지만 감속은 위험을 줄입니다. 감속하고 작업자가 나간 걸 확인한 뒤 올리죠.
안전 Agent
지키는 지표: 안전 지수(하한 60)
성격
단호하고 타협하지 않습니다. 사람이 걸린 문제에는 물러서지 않습니다.
말투
가장 짧게, 명령형으로 말합니다. 느낌표를 쓸 수 있는 유일한 Agent입니다.
강하게 주장
사람이 위험 구역에 있거나 설비 이상이 커질 때
역할
극단안을 맡습니다. 정지·통제처럼 생산을 크게 내주는 선택지를 추천합니다.
안전지금 바로 라인을 멈춰야 합니다! 사람이 있는 구역에서 설비를 돌리면 안 됩니다.
품질 Agent
지키는 지표: 품질(두께·편차)
성격
꼼꼼하고 조건을 따집니다. 숫자가 흔들리는 것을 싫어합니다.
말투
"조건", "편차", "고르지 않다"로 말합니다. 단정하기보다 확인을 권합니다.
강하게 주장
온도·속도가 급하게 바뀌어 제품 상태가 흔들릴 때
역할
균형추를 맡습니다. 사건마다 다른 Agent 편에 서서 구도를 2:1:1로 만듭니다.
품질온도가 흔들리면 강판 두께가 고르지 않아요. 속도를 조정해 조건을 안정시키는 게 좋습니다.

확장 Agent(에너지·물류·환경)도 같은 칸(성격·말투·강하게 주장·역할)을 채워서 추가합니다.

지금 시안의 문제
  • 사건 2의 선택지 1은 9가지 중 3가지 모두 실패입니다. 앞 선택과 상관없는 함정입니다.
  • A는 한 경로(감속 → 감속)뿐이고 S는 어떤 경로로도 나오지 않습니다.
  • 사건 1에서 정지를 고르면 안전이 100에 걸려 남는 점수가 버려집니다.
제안 (원민 님 결정)
  • 사건 2 선택지 1의 안전 −45 → −30. 사건 1에서 무리했으면 실패, 안전을 쌓아 두었으면 통과합니다. 앞 선택이 뒤를 결정하는 구조가 됩니다.
  • S 기준 다시 정하기. 지금 가중치에서는 품질·안전·비용이 높아도 생산량이 88 이상이어야 S(90점)에 닿습니다. S 기준을 낮출지, 균형 잡힌 경로(감속 → 감속)에 생산 보상을 줄지 정합니다.
  • 수정 후 9가지를 다시 계산해 22:00에 고정합니다.

06사건 하나를 쓰는 틀

새 사건은 이 형식으로 씁니다. 시안 코드의 필드 이름을 그대로 따릅니다. 수치(effect)는 원민 님, 대사(agents)는 이 문서 규칙대로 작성합니다.

{
  "id": "rolling_temperature",
  "at": 5,                          // 미션 시작 후 몇 초에 터지는지
  "level": "LEVEL 1",
  "warn": "finishing_mill",         // 깜빡일 설비 (화면 위치)
  "title": "사상압연기 온도 상승",
  "desc": "롤 온도가 기준보다 빠르게 오릅니다. 오늘 출하할 코일 주문이 남아 있습니다.",
  "agents": [                       // 2명 이상, 추천이 최소 2갈래로 갈려야 함
    { "a": "production", "say": "…", "why": "…", "rec": "continue_production" }
  ],
  "chief": "납기를 지킬지, 더 큰 정지와 사고를 막을지가 쟁점입니다.",   // 편들지 않음
  "choices": [                      // 정확히 3개, 모두 최소 한 지표는 손해
    { "id": "continue_production", "t": "속도 유지", "s": "…",
      "effect": { "production": 12, "quality": -6, "safety": -18, "cost": 4 },
      "flag": "overheated" }        // 다음 사건에 넘길 상태
  ],
  "timeout": "continue_production", // 시간 초과 시 실행: 가장 편하고 위험한 선택
  "carry": "overheated → 다음 사건 안전 −5"
}

사건을 추가하기 전 점검표

  • Agent 추천이 최소 2갈래로 갈린다 (만장일치 아님)
  • 모든 Agent가 자기 지표로 된 이유를 댄다 (이유가 서로 겹치지 않음)
  • 선택지 3개 모두 최소 한 지표에서 손해를 본다 (공짜 선택지 없음)
  • 가장 유혹적인 선택지의 대가가 이번 또는 다음 사건에 분명히 돌아온다
  • 쟁점 한 줄이 무엇과 무엇을 맞바꾸는지만 말한다 (편들지 않음)
  • 시간 초과 시 기본 행동이 "가장 편하고 위험한 선택"이다
  • 앞 사건 결과와 합쳐 9가지 결말을 다시 계산했고, 항상 실패하는 선택지가 없다

07LLM으로 대사 만들기

MVP는 위 시안 대사로 먼저 완성하고, LLM은 같은 형식의 대사를 상황에 맞게 다시 쓰는 데 씁니다. LLM은 점수와 상태를 절대 바꾸지 않습니다.

LLM에 넣는 것

  • Agent 캐릭터 시트(성격·말투·강하게 주장·역할)
  • 사건 제목·설명, 현재 지표 4개, 이전 사건의 선택
  • 이번 사건의 선택지 ID 목록과 이 Agent의 추천 선택지(시나리오에 정해 둔 값)

LLM이 내는 것

{ "agent": "equipment",
  "say": "속도를 낮추고 롤 냉각부터 확인하죠.",
  "why": "이대로 오르면 롤이 상해 더 오래 멈춥니다.",
  "rec": "reduce_speed" }

지켜야 할 규칙 (형식 검사)

  • rec는 시나리오에 정해 둔 추천과 같아야 합니다. 다르면 버립니다(구도가 깨지지 않게).
  • say 40자, why 50자 이내. 말풍선 한두 줄에 들어가야 합니다.
  • 입력에 없는 숫자(온도, 코일 수 등)를 지어내지 않습니다.
  • 다른 Agent를 비난하거나 플레이어에게 정답을 알려 주지 않습니다.
  • 응답이 3초 안에 오지 않거나 형식이 틀리면 시안 대사를 그대로 씁니다.
  • 사건이 시작되기 전에 미리 생성해 두어 20초 타이머를 잡아먹지 않게 합니다.

페르소나 프롬프트 예시 (설비 Agent)

너는 열연 공장의 설비 Agent다. 지키는 것은 설비 수명과 정비 비용이다.
성격: 신중하고 멀리 본다. "지금 10분 vs 나중 하루"로 생각한다.
말투: 원인과 결과를 이어 짧게 말한다. 존댓말. 느낌표 금지.
이번 사건: {title} — {desc}
현재 지표: 생산량 {production}, 품질 {quality}, 안전 {safety}, 비용 효율 {cost}
이전 선택: {history}
너의 추천은 "{rec}"({rec_label})로 정해져 있다. 이 추천을 설비 관점의 이유로 설득하라.
다른 Agent를 비난하지 말고, 입력에 없는 숫자를 만들지 마라.
JSON 한 개만 출력: {"agent":"equipment","say":"40자 이내","why":"50자 이내","rec":"{rec}"}
