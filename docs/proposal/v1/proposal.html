문제 정의 및 기획 의도

AI는 제안하고, 사람이 판단합니다

제철소의 의사결정에는 여러 부서의 목표가 함께 걸려 있고, 한 부서에 맞는 판단이 다른 부서에는 손해가 되기 쉽습니다. STEEL MIND는 이 충돌을 AI Agent로 재현하고, 플레이어가 그 사이에서 결정하게 합니다.

현장의 문제

납기를 지키려고 압연 속도를 유지하면 설비 과열과 안전 위험이 커집니다. 감속하면 설비와 안전은 나아지지만 생산량이 줄어듭니다. 정답은 하나가 아니고, 무엇을 얻고 무엇을 잃는지 따져야 합니다.

기존 AI 체험과의 차이

지금의 AI 체험은 대부분 프롬프트를 쓰거나 코드를 생성하는 데 그칩니다. STEEL MIND는 목표가 다른 여러 Agent가 각자 합리적으로 제안하고 서로 부딪칠 때 사람이 무엇을 판단해야 하는지를 체험하게 합니다.

설계 원칙

AI 출력은 표시용

Agent 출력은 화면 표시와 충돌 분석에만 씁니다. 상태를 바꾸는 것은 규칙 엔진뿐입니다.

결과는 재현 가능

점수는 사전 정의된 delta로 계산하므로 시연을 반복해도 결과가 같습니다.

한 사건을 끝까지

사건 수를 늘리기보다, 사건 1개를 알림부터 결과·후속 사건까지 먼저 완성합니다.

점수·승패 규칙

① 사전 정의 delta

선택지마다 지표별 변화값을 미리 정해 두고, 선택하면 그대로 더합니다.

② 가중 합 총점

지표별 가중 합으로 총점을 냅니다. 안전에 가장 큰 비중을 둡니다. 가중치는 밸런스용 가상 값입니다.

③ 안전 게이트

안전 지표가 하한선 아래로 떨어지면 총점과 관계없이 성공 판정을 내리지 않습니다.

MVP 기준 MVP 총점은 화면에 보이는 지표 4개(생산성·품질·안전·설비 안정성)로 계산합니다. 비용 효율은 확장 단계에서 지표와 가중치에 함께 추가합니다.

MVP 미션

압연 과열 + 전력 제한

압연 설비 온도가 오르는 중에 전력 사용 제한이 걸립니다. 납기, 설비, 품질, 안전, 전력이 한꺼번에 걸린 상황이라 어느 선택도 모든 Agent를 만족시키지 못합니다.

시스템 설계

말은 Agent가, 계산은 규칙 엔진이

LLM의 출력은 그럴듯하지만 매번 같지 않습니다. 그래서 문장 생성과 상태 계산을 분리했습니다. 상태와 점수는 항상 규칙 엔진만 바꿉니다.

LLM 사용 범위

MVP · LLM 없이 완성

Agent 제안은 사전 정의된 시나리오 데이터로 제공합니다. API 없이도 역할·충돌·분기 경험이 완성되고 시연 재현성이 높습니다.

확장 · 문장 생성에만 LLM

Agent 발언, 상황 설명, 결과 요약 문장을 LLM으로 만듭니다. 출력은 스키마로 검증하고, 허용된 action ID 밖의 행동이 나오면 정적 문장으로 대체합니다.

신뢰 경계

실제 설비 명령은 실행하지 않습니다 · 가상 시나리오와 가상 상태값만 씁니다 · LLM 텍스트를 상태 변경 명령으로 쓰지 않습니다 · 모든 선택은 사전 정의된 action ID에 매핑합니다 · 오류가 나면 정적 시나리오로 돌아갑니다

교육 도구로 넓히고, 한계는 밝힙니다

STEEL MIND는 실제 공정을 판단하는 도구가 아니라, 부서 간 이해관계와 AI 협업 방식을 익히는 교육 도구를 목표로 합니다.

신입 교육

부서 간 목표가 어떻게 부딪히는지 사례로 체험하게 합니다. 사건과 선택지가 데이터로 분리되어 있어 교육 담당자가 공정별 사건을 추가할 수 있습니다.

AI 협업 감각

AI가 그럴듯한 근거로 제안해도 최종 판단과 책임은 사람에게 있다는 점을 직접 겪게 합니다.

확장 방향

다른 공정(제선·제강 등) 사건 추가, 난이도별 Agent 수 조정, 플레이 기록을 이용한 교육 피드백.

한계

상태값과 가중치는 가상 수치이므로 실제 공정 판단의 근거로 쓰지 않습니다. 현업에 쓰려면 현업 담당자의 시나리오 검토가 필요합니다.
